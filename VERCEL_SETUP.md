# Vercel setup

Vercel serves the application at `https://agenticsl.vercel.app`. The original ChatGPT Sites sign-in route and D1 binding are hosting-specific and are not provided by Vercel. This deployment uses Supabase Auth and PostgreSQL through `api/index.mjs` and `src/vercel.mjs`.

## Finish setup

1. Connect a Supabase project for this app. Use an existing suitable project or create one through your Supabase account after checking its plan and limits.
2. Apply `supabase/schema.sql` to that project's database as a reviewed schema migration. It creates the append-only learning table, grants and row-level security. Do not run the SQLite migration in `drizzle/` against PostgreSQL. Use the migration version generated by Supabase tooling when recording migration history.
3. Create your private owner account in Supabase Authentication and confirm its email. Set the password yourself in Supabase; do not paste it into chat or commit it to source. This app has no public sign-up form. Disable public sign-ups for a single-user project.
4. Add these Vercel Production environment variables:

| Variable | Value |
| --- | --- |
| `APP_ORIGIN` | `https://agenticsl.vercel.app` |
| `SUPABASE_URL` | Your project's `https://PROJECT_REF.supabase.co` URL |
| `SUPABASE_ANON_KEY` | Its publishable or legacy anon key; never a secret/service-role key |
| `AGENTICSL_OWNER_ID` | The UUID of your confirmed owner account |

5. Redeploy the latest `main` commit. Keep existing Vercel deployment protection enabled. The app performs its own owner authentication as well.
6. Open the production URL, sign in with your owner account, check an objective and reload. Confirm the saved objective remains. Sign out and confirm `/api/state` returns 401. A configuration-complete `/api/health` is not proof of database readiness; a saved-and-reloaded record tests the actual persistence path.

The repository's `vercel.json` explicitly routes requests to the Vercel adapter. Vercel settings should not override it with a static export or the local development server. Production sign-in and POST requests use `APP_ORIGIN`; previews with another origin intentionally cannot log into the production workspace.

## Authentication and data boundaries

- Supabase handles password verification and session issuance. The app validates the current access token against Supabase's `/auth/v1/user` endpoint and checks the configured owner UUID and confirmed email.
- Browser sessions use Secure, HttpOnly, SameSite=Lax cookies. Expired access tokens can be refreshed through Supabase's refresh-token endpoint; rotated tokens are written back as cookies.
- Browser mutations, login and logout require the exact configured Origin. The public adapter discards caller-supplied `oai-authenticated-*` identity headers and injects identity only after verification.
- Database calls use the owner's verified token and publishable/anon key. PostgreSQL row-level security remains active. No service-role key is needed. Requests cannot read or append another user's records.
- Credentials, cookies and private learning evidence are not included in the deployment artifact or source repository.
- The local `npm run dev` adapter is for loopback development only. It uses a development identity and a separate SQLite file; it is not the Vercel production entrypoint.

## ChatGPT accounts and MCP

`POST https://agenticsl.vercel.app/mcp` accepts a verified Supabase bearer access token for the configured owner. Browser cookies are not accepted at this endpoint. Learning tools use the same database as the dashboard.

This bearer endpoint alone is **not a finished ChatGPT OAuth connection**. To finish native account authorization, enable Supabase OAuth 2.1 server capabilities, register the permitted MCP client, add an explicit consent UI and protected-resource discovery, and test authorization, token refresh and revocation. Do not paste a long-lived token into a prompt or make learning data public to connect an account. Both ChatGPT accounts must separately authorize the same learning owner account. Chat histories remain separate.

The automatic plugin provisioned by ChatGPT Sites applies to a published Site. It is not automatically provisioned by this Vercel deployment. Until the OAuth connection is completed, use the dashboard and manual review entry, or a development MCP client with a properly obtained short-lived access token.

## Current release limits

The adapter tests mock the provider to verify app routing, owner checks, spoofed-identity rejection, Origin handling, cookie rotation, pagination and error behavior. A live Supabase project, applied SQL policies and real sign-in are still required for end-to-end verification. No live account or password is created by the tests.
